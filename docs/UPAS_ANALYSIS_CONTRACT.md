## Host bandwidth and acquisition coverage

Host BW Total = completion-counted Read + Write payload in the graph cohort. Discard, Flush and Other extent sizes are excluded from transferred bytes. Their measured execution still contributes to active time. All three directions share the same wall-clock denominator. With Idle divides by the explicit analysis interval; w/o Idle divides by its clipped union of device-wide issue-to-completion activity. Process/FilePath/operation filters change payload, while activity includes all source processes and operations on selected devices, before detail retention and time-window eviction.

Completions in the inclusive selection interval contribute their full payload even when issued before its start. Activity is clipped at both boundaries; requests completing later still contribute activity. Point selections use the observed request span. Adjacent inclusive selections may share an endpoint request. Multiple devices sum payload and use the union where any selected device is active, not summed device-seconds. Stacked device layers may represent the same physical transfer. Units are MiB/s, using 1,048,576 B/MiB. Zero denominators and unknown activity coverage produce unavailable values, never NaN/Infinity or fabricated zero.

Production Perfetto w/o Idle is a **reconstructed estimate**, not a claim of exact physical-device idle. It requires the recorded unfiltered issue/complete recipe marker, complete raw quality (no reported kernel/service loss, parse/truncation/projection/clock/flush errors), matching saved event/footer counts and graceful close. Device-specific eligibility additionally requires no unresolved timing, unmatched issues or requeues and matching per-device observations. Incomplete unrelated devices do not invalidate an eligible selected device. Older/imported/sampled sources without scope proof stay unavailable; the observed active-time lower bound remains visible. Reanalyzing raw data preserves a valid recording scope header but does not manufacture one or override failed raw quality.

## Detail timing and uPAS differences

Optional `CompletedIo.detail_timing` is serde-default and backward compatible with schema6 sessions. New raw eBPF sessions compute per-device observed QD after issue and per-device D2D/C2C gaps before filters. Raw eBPF session reload recalculates these fields. Existing serialized observed completions lacking the fields remain unmeasured until raw Perfetto reanalysis. Perfetto issue QD is reconstructed from uniquely paired half-open intervals, with completion before issue at equal time, and collapsed partial completions sharing an issue; unpaired requests are absent. This is observed detail QD, not hardware queue identity or an unsampled queue. Legacy all-device depth after completion remains a separately labelled axis.

D2D/C2C gaps use the preceding same-device observed event before analysis filters. First and invalid-order differences are unavailable. uPAS UpasAnalyzer.py991/995 uses global shifts after filename sorting; device separation avoids cross-device/cross-file boundary subtraction. These Explore points use the existing completion-time x axis, explicitly described in Summary. Normalized latency = measured device latency in ms / size in KiB for nonzero R/W requests. uPAS998 substitutes zero for zero-size commands; this implementation excludes undefined values.

CDF is the exact empirical fraction <= each value, including all ties; sorted rank is1-based. Up to512 original values are rendered with interpolated connecting lines. CSV includes every sorted sample and each exact cumulative count. Category pies use the same graph cohort: one membership per command/access/size/device/CPU/device+Process identity, or explicitly overlapping file/layer memberships. Counts and R/W payload weights have separately displayed denominators. Top4 plus a remainder slice is presentation only; every category remains in the paginated table and CSV.

LBA spatial payload assigns whole Read/Write bytes to16 equal-width starting-sector bins per device. It measures traffic locality, not unique occupied space. Temporal locality sorts measured issue timestamps per device, direction and starting LBA within the current graph cohort and takes consecutive differences. First visits/missing issue timestamps are excluded. Overlapping ranges with different starts do not count as temporal reuse; the separate Address access counts handle partial overlap. uPAS2932–2965 mutates its dataframe while iterating directions; both directions are preserved independently here.

## Rolling observed bandwidth

Rolling C2C/D2D uses64 consecutive same-device observed gaps with the aligned64-row R/W payload. The first event has no gap; the first64 observations are warmup. Undefined payload/gap, zero duration and checked-sum overflow remain unavailable until the offending row ages out. Optional rate fields preserve old schema6 observed sessions; raw eBPF reload and raw Perfetto reanalysis compute them before analysis filters and retention. Process/Read filters select endpoint requests and retain their original device-wide rate, not a filtered or directional throughput. Both use the existing completion-time x axis.

Actual uPAS code sets ws=64 while graph titles say32. Its rolling denominators additionally include service latency of the first cohort request. On an equal130-event fixture (1KiB each,1ms event spacing,0.5ms service), executed uPAS assignments produce64.5ms and0.969MiB/s after4-decimal rounding; the explicit observed-gap definition here produces64ms and0.9765625MiB/s. This deliberate difference avoids adding service time to an already defined event-to-event clock. Rolling samples are observed-detail rates, not unsampled hardware throughput.

If every source request is unplottable for the selected metric, graph payload and both BW results are unavailable rather than measured zero. The source device activity clock can remain known independently. A genuinely empty measured filter remains a distinct state.

## Continuous Busy / Idle intervals

A positive maximal continuous interval is one statistical sample. Busy merges overlap and adjacency across selected devices from full-source issue/completion activity. Idle is its complement inside the current analysis interval. Boundaries clip runs/gaps; unknown coverage yields no fabricated intervals. Process/FilePath/operation filters change request cohorts and payload, never the device activity union. This population is distinct from per-request zero-filled values or active/idle milliseconds per fixed window.

Interval trends show centers against duration in ms; linked Summary has exact histogram/percentiles/CDF. Full graph retains all filtered analysis-range I/O for request summaries and Host BW. An explicit interval selection uses completions in (start,end], assigning a closing completion to Busy instead of the following Idle gap. A selected idle interval can have a valid duration distribution with zero request rows. For multi-interval/window selections the BW clock is the first-to-last selected time envelope, including intervening time; Y selection filters payload within that clock. CSV exports each interval boundary, duration and contributing request/payload count separately.

Executed actual uPAS UpasParser.common_calculate and UpasAnalyzer1007-1011 on overlapping intervals [0,2],[1,5],[7,8]ms. Its default Max_QD_Value64 produces busy=[0,0,0]; a threshold2 produces [0,3,3] because the field is inter-completion spacing gated by complete_q==max_qd_value-2. Idle is [0,0,2], including zero-filled request rows. Continuous durations here are Busy=[5,1], interior Idle=[2]. The corrected union definition deliberately avoids threshold dependence and per-request zero weighting. Source histogram functions7967/8044 actually draw sorted percentile curves; both exact CDF and histogram are provided in linked Summary.

## Idle-separated payload bursts

Device-wide activity runs merge when intervening Idle <=500000ns. A greater gap starts a new burst. Eligible complete/reconstructed activity is required; sampled/unproven sources cannot fabricate burst boundaries. Analysis boundaries clip the bursts. Filters affect retained R/W payload while device-wide burst boundaries stay fixed, so another process cannot be erased into fake Idle. Whole-range cumulative payload remains a separate existing preset.

Main curves show completion-counted step accumulation within each burst for Total/Read/Write, including the first request and excluding non-R/W extent bytes. Center markers show final totals and define rectangle selection; a click selects the containing burst. Linked Summary has one final-total sample per burst, including zero filtered payload, rather than weighting by the number of intermediate cumulative points. CSV contains every cumulative timestamp/byte value plus final burst totals and bounds. Completion cohort and Host BW envelope follow the continuous-interval rules above.

Executed actual uPAS assignments3133/3139/3155-3157 on payloads1/2/4MiB with Idle0/0.5/0.500001ms. It splits the third request but masks its payload to zero, yielding cumulative[1,3,0]MiB. The corrected first-request-inclusive implementation yields[1,3,4]MiB. uPAS uses send-order per-row idle on the filtered dataframe; this implementation explicitly uses completion-counted retained payload with a full-source device clock. These differences are deliberate and verified.
