## Host bandwidth and acquisition coverage

Host BW Total = completion-counted Read + Write payload in the graph cohort. Discard, Flush and Other extent sizes are excluded from transferred bytes. Their measured execution still contributes to active time. All three directions share the same wall-clock denominator. With Idle divides by the explicit analysis interval; w/o Idle divides by its clipped union of device-wide issue-to-completion activity. Process/FilePath/operation filters change payload, while activity includes all source processes and operations on selected devices, before detail retention and time-window eviction.

Completions in the inclusive selection interval contribute their full payload even when issued before its start. Activity is clipped at both boundaries; requests completing later still contribute activity. Point selections use the observed request span. Adjacent inclusive selections may share an endpoint request. Multiple devices sum payload and use the union where any selected device is active, not summed device-seconds. Stacked device layers may represent the same physical transfer. Units are MiB/s, using 1,048,576 B/MiB. Zero denominators and unknown activity coverage produce unavailable values, never NaN/Infinity or fabricated zero.

Production Perfetto w/o Idle is a **reconstructed estimate**, not a claim of exact physical-device idle. It requires the recorded unfiltered issue/complete recipe marker, complete raw quality (no reported kernel/service loss, parse/truncation/projection/clock/flush errors), matching saved event/footer counts and graceful close. Device-specific eligibility additionally requires no unresolved timing, unmatched issues or requeues and matching per-device observations. Incomplete unrelated devices do not invalidate an eligible selected device. Older/imported/sampled sources without scope proof stay unavailable; the observed active-time lower bound remains visible. Reanalyzing raw data preserves a valid recording scope header but does not manufacture one or override failed raw quality.

## Detail timing and uPAS differences

Optional `CompletedIo.detail_timing` is serde-default and backward compatible with schema6 sessions. New raw eBPF sessions compute per-device observed QD after issue and per-device D2D/C2C gaps before filters. Raw eBPF session reload recalculates these fields. Existing serialized observed completions lacking the fields remain unmeasured until raw Perfetto reanalysis. Perfetto issue QD is reconstructed from uniquely paired half-open intervals, with completion before issue at equal time, and collapsed partial completions sharing an issue; unpaired requests are absent. This is observed detail QD, not hardware queue identity or an unsampled queue. Legacy all-device depth after completion remains a separately labelled axis.

D2D/C2C gaps use the preceding same-device observed event before analysis filters. First and invalid-order differences are unavailable. uPAS UpasAnalyzer.py991/995 uses global shifts after filename sorting; device separation avoids cross-device/cross-file boundary subtraction. These Explore points use the existing completion-time x axis, explicitly described in Summary. Normalized latency = measured device latency in ms / size in KiB for nonzero R/W requests. uPAS998 substitutes zero for zero-size commands; this implementation excludes undefined values.

CDF is the exact empirical fraction <= each value, including all ties; sorted rank is1-based. Up to512 original values are rendered with interpolated connecting lines. CSV includes every sorted sample and each exact cumulative count. Category pies use the same graph cohort: one membership per command/access/size/device/CPU/device+Process identity, or explicitly overlapping file/layer memberships. Counts and R/W payload weights have separately displayed denominators. Top4 plus a remainder slice is presentation only; every category remains in the paginated table and CSV.

LBA spatial payload assigns whole Read/Write bytes to16 equal-width starting-sector bins per device. It measures traffic locality, not unique occupied space. Temporal locality sorts measured issue timestamps per device, direction and starting LBA within the current graph cohort and takes consecutive differences. First visits/missing issue timestamps are excluded. Overlapping ranges with different starts do not count as temporal reuse; the separate Address access counts handle partial overlap. uPAS2932–2965 mutates its dataframe while iterating directions; both directions are preserved independently here.
